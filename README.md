# Cargoship, Rancher RKE2

Hardened [cargoship](https://github.com/colonel-byte/cargoship) package definitions for Rancher RKE2, published to `ghcr.io/colonel-byte/cargoship/rancher-rke2`.

## Layout

Everything under `packages/` is **generated**. There is no hand-written `distro.yaml`.

| Path                         | What it is                                                                                                                                                      |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `templates/distro.yaml.tmpl` | The definition. Everything that does not vary by version - sysctls, fapolicyd, CIS arguments, pod security, the cilium `HelmChartConfig` - lives here literally |
| `versions/<version>.yaml`    | Only what varies by version: the version strings, the RPM digests, and the image list. Generated by `hack/new-version.sh`                                       |
| `versions/tracked.yaml`      | The rke2 minor lines to chase upstream                                                                                                                          |
| `packages/<version>/`        | The rendered definitions, committed. Never hand-edited                                                                                                          |

To change what the package installs, edit the template. To add a version, run the script. Editing a file under `packages/` is lost on the next render.

## Adding a version

```sh
hack/new-version.sh v1.37.2+rke2r1
cargoship dev render -t templates/distro.yaml.tmpl -f versions/1.37.2-rke2r1.yaml -o packages/1.37.2-rke2r1
```

The script resolves the image list from upstream's own `rke2-images-core` and `rke2-images-cilium` release assets, hashes the RPMs the definition declares, and picks the `etcdctl` release matching the `hardened-etcd` image the release bundles. It writes nothing if an artifact is no longer fetchable, which is what upstream retiring a revision looks like.

## What is installed beyond rke2

`etcdctl` is uploaded to `/usr/local/bin/etcdctl` on control-plane nodes only. rke2 bundles etcd but exposes no client, and this is the tool you want when etcd is the thing that is wrong. Its version is derived from the `hardened-etcd` image each release ships rather than pinned, so the client always matches the server - which is why it differs across lines (1.35.0 gets 3.6.7, 1.37.2 gets 3.7.1).

Normally nobody runs either by hand: [`render.yaml`](.github/workflows/render.yaml) does both weekly and opens a pull request with whatever moved.

## How a version reaches the registry

1. `render.yaml` chases upstream, renders, and opens a pull request against `main`. It publishes nothing.
2. Merging it is the review gate - the diff to read is the definition.
3. `release.yml` publishes every version under `packages/` that the registry does not already hold, and tags what shipped as `rancher-rke2/<version>`.

Step 3 is idempotent: a push that changes neither a definition nor the registry publishes nothing, and a version whose push failed is picked up by the next run.

## Requirements

`cargoship` v0.39.0 or newer, for `cargoship dev render`. CI pins it through the `CARGOSHIP_VERSION` repository variable.
